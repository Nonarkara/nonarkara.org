# Security audit · nonarkara.org · 2026-10-07

Scope: the static Cloudflare Pages client, its service worker, GitHub Actions,
and the `api.nonarkara.org` Worker. This is a source-and-runtime review, not a
formal penetration test.

## Executive read

Current confidence: **7/10**, up from approximately **5/10** before this pass.
The site has a small static attack surface and no browser-side authentication,
but it previously sent visitor network/browser metadata to a public third-party
collector and exposed an unconstrained capture write endpoint. Both paths are
now bounded. The remaining material risks are operational: broad inline-style
permission, third-party availability, and the need to rotate or remove unused
Worker secrets outside source control.

## 1. Secrets and repository history

- `gitleaks git` found **0** verified secrets across reachable history.
- No credential was added to source. Worker integrations continue to read
  deployment secrets from environment bindings.
- GitHub Actions are pinned to immutable commit SHAs.

Score: **8/10**. Verify deployed secret inventory periodically; source review
cannot prove whether an old Cloudflare secret is still configured.

## 2. Browser and privacy boundary

- Removed the client-side IP, user-agent, referrer, and full-page collector.
- Added a restrictive Content Security Policy, clickjacking denial, MIME
  sniffing denial, opener isolation, HSTS, and a constrained Permissions Policy.
- Added SRI to the externally hosted QR library.
- External command-palette windows open with `noopener,noreferrer`.

Score: **8/10**. `style-src 'unsafe-inline'` remains because the current UI uses
extensive inline style attributes and generated style strings. Removing that
permission needs a deliberate styling migration, not a one-line policy change.

## 3. API and data boundary

- `/capture` now accepts only production origins, POST/OPTIONS, JSON, a maximum
  8 KiB body, bounded text/tags/session metadata, and 12 writes per IP hash per
  minute.
- Rate-limit keys store a truncated SHA-256 digest, not raw IP addresses.
- Error responses no longer disclose internal exception text.
- Public read endpoints remain intentionally cross-origin readable.

Score: **7/10**. Rate limiting is KV-based and therefore eventually consistent;
it is abuse friction, not a transactional quota. If capture becomes valuable or
sensitive, add user authentication and a durable limiter.

## 4. Supply chain

- Three.js is vendored and currently reports no known OSV finding for 0.160.0.
- The remaining CDN script is versioned and integrity checked.
- CI runs a pinned Gitleaks action on pushes and pull requests.

Score: **8/10**. Recheck the vendored Three.js version when upgrading; a vendored
file does not receive automated dependency alerts.

## 5. OWASP / STRIDE review

| Area | Present control | Residual concern |
|---|---|---|
| Spoofing | Exact capture Origin allowlist | Origin is not user identity |
| Tampering | Schema and size validation | Public clients can still submit valid noise |
| Repudiation | Timestamped server records | No authenticated actor trail |
| Information disclosure | Collector removed; generic errors; CSP | Public status data is intentionally open |
| Denial of service | Body cap and write throttle | Distributed traffic can exceed per-IP limits |
| Elevation of privilege | No browser admin surface | Worker secrets remain high-value deployment state |

## 6. Agent and model exposure

The shipped browser does not execute an agent or accept tool instructions. The
Worker's optional OpenAI fan-out receives only the sanitized capture record and
has no tool authority. Prompt injection therefore has low consequence today.

Score: **8/10**. Reassess before adding retrieval, tools, privileged actions, or
automatic publication from captures.

## 7. Verification and trend

- Static regression test recomputes every allowed inline-script CSP hash.
- Worker tests cover origin confusion, payload shape, metadata allowlists, and
  date-stable uptime folding.
- Production verification must confirm the custom domain actually serves the
  policy; Cloudflare zone cache rules have overridden repository headers before.

This is the first scored report in this repository, so there is no earlier
like-for-like trend line. Future audits should compare against the seven scores
above and record new findings rather than silently replacing them.
